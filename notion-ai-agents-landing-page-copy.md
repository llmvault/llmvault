## Executive Summary

Notion is not selling "AI chat." It is selling labor inside an existing workspace. The page strategy is to make agents feel like teammates that can use company context, run recurring workflows, and stay governable enough for Business and Enterprise buyers.

The strongest copy move is the shift from prompt output to finished work. Notion repeatedly frames agents as:

- Always-on team members, not one-off assistants.
- Built into the place where work already lives.
- Able to act, not just answer.
- Safe enough for admins because permissions, logs, and reversible changes are prominent.
- Valuable because one person can configure a workflow and the whole team benefits.

For Hivy, the equivalent strategic angle should not be "AI coworker." That is too broad now. The sharper version is: Hivy gives teams specialist AI agents that work in real, isolated workspaces with the tools needed to finish technical, research, data, content, and support work.

## What Notion Makes Important

1. Finished work, not generated text.
   The hero and first feature blocks focus on agents doing assigned tasks. Notion quickly gets away from "ask AI" and into recurring reports, routing, Q&A, page edits, database updates, and cross-tool research.

2. Team-wide automation.
   Custom Agents are positioned as shared resources. One person sets up the workflow, then the team gets leverage from it. This is much stronger than individual productivity copy because it gives managers and admins a clear reason to care.

3. Context as the moat.
   Notion's biggest strategic asset is that the work already lives in Notion. The page keeps returning to docs, databases, connected tools, Slack, Mail, Calendar, GitHub, Google Drive, and web context.

4. Clear distinction between personal and custom agents.
   The page separates on-demand personal help from autonomous team workflows. This prevents the product from feeling vague.

5. Trust, safety, and admin control.
   Enterprise confidence is not buried. Permissions, audit trails, usage analytics, reversible changes, zero data retention, compliance, and prompt-injection protection all become conversion copy.

6. Use cases before technical architecture.
   They do not lead with models, reasoning, memory, or orchestration. They show recognizable workflows: Q&A, routing, status updates, meeting notes, search, onboarding, feedback triage, support, and security alerts.

7. Pricing tied to automation volume.
   Custom Agents use a credit model. Notion explains that more agent work consumes more credits, which keeps the pricing story aligned with value delivered.

## Landing Page Strategy Breakdown

### Above The Fold

The page uses an immediately understandable promise: an AI team that works all the time. The subhead makes the interaction model simple: assign tasks, agents do the work. That is useful because it removes the need to explain agents technically in the hero.

The CTAs split self-serve and sales:

- Try for free.
- Request a demo.

This tells visitors the product is accessible, but also enterprise-ready.

### Proof Bar

Notion places recognizable company logos near the top. This is especially important because "AI agents" is a credibility-sensitive category. The proof bar says: serious teams are already testing this kind of workflow.

### First Product Claim

The first real section is not a feature matrix. It is a job-to-be-done: automate recurring work for the team. This is the right hierarchy because it frames all later features as supporting automation, not as independent capabilities.

### Use-Case Cards

The page highlights three simple agent categories:

- Q&A.
- Task routing.
- Status updates.

These are basic, but that is the point. They are recurring, easy to imagine, and painful at scale. They also map to different buyer types: knowledge teams, operations teams, and managers.

### Builder Moment

"Create your own" matters because Notion wants the product to feel flexible without sounding technical. The page avoids "workflow builder" as the primary framing and says plain language is enough.

### Personal Agent Section

The personal agent section extends the same product logic to on-demand work. It says the personal agent can perform actions inside Notion, then supports that with personalization, privacy, and memory.

### Context Section

This is the strategic center of the page. Notion's agent promise depends on context. The page says agents work where the team already works and can connect to relevant tools. This removes the biggest adoption objection: "Will we have to rebuild our knowledge base somewhere else?"

### Enterprise Control Section

The page moves from promise to reassurance. It tells admins that agent runs are logged, permissions are scoped, changes can be undone, and data remains private. This is essential because autonomy increases perceived risk.

### FAQ

The FAQ handles the core conversion objections:

- What are Custom Agents?
- How are they different from the personal agent?
- Who can create them?
- Which tools are compatible?
- What can admins control?
- Is data secure?
- How does pricing work?

The FAQ is doing sales support, product education, and risk reduction at the same time.

## Copy Patterns Worth Reusing

- Use a teammate metaphor, but attach it to concrete work.
- Keep the hero extremely short.
- Name familiar workflows before naming infrastructure.
- Separate personal assistance from team automation.
- Say "set it up once" when the product has recurring automation.
- Pair every autonomy claim with a control claim.
- Show enterprise controls before the reader has to ask for them.
- Use customer proof near high-risk promises.
- Keep technical details in docs, not the main pitch.

## Strategic Gaps Hivy Can Exploit

Notion's page is strong, but it is naturally constrained by Notion's workspace. Hivy can differentiate by making "real work environment" the center:

- Agents work in cloud sandboxes, not only documents.
- Specialists have their own tools: terminal, browser, Git, SQL, notebooks, charts, and connected apps.
- Work can end in durable artifacts: pull requests, reports, charts, replies, docs, and investigated tickets.
- Sessions can be reviewed, shared, interrupted, and resumed.
- Teams can choose the right model per agent or task.
- Technical teams can see the work, not just the answer.

The copy should make Hivy feel less like "AI inside docs" and more like "a bench of specialists with secure workspaces."

## FAQ

What is Hivy?

Hivy is a workspace for specialist AI agents. Each agent is built for a type of work and can use the tools needed to complete that work, including sandboxes, browsers, terminals, Git, SQL, charts, files, and integrations.

How is this different from a chatbot?

A chatbot mainly replies. Hivy agents can work. They run tools, inspect context, create files, generate artifacts, and keep a reviewable trail of what happened.

Which agents are available?

Hivy includes specialists for software engineering, research, data analysis, content writing, and support engineering.

Is Hivy for technical teams only?

Question:

Can I run Hivy locally?

Yes. The repository includes a local development stack for the web app, API, worker, sandbox runtime, database, Redis, and supporting services.

# Copy Strategy For Hivy

## Positioning

Primary positioning:

Hivy is the agent workspace for teams that need AI to do work with tools.

Shorter version:

AI agents with real workspaces.

More technical version:

Sandboxed AI agents for coding, research, data, content, and support workflows.

## Message Hierarchy

1. Outcome: agents finish work.
2. Mechanism: each agent gets the right tools in a secure workspace.
3. Differentiation: not just chat, actual execution and reviewable artifacts.
4. Breadth: multiple specialists for different team workflows.
5. Trust: scoped sessions, visibility, review, model control.

## Voice

Use plain, concrete language. Avoid abstract AI-platform language unless the section is for technical buyers.

Good nouns:

- Agent.
- Specialist.
- Sandbox.
- Session.
- Tools.
- Pull request.
- Report.
- Chart.
- Ticket.
- Review trail.

Weak nouns:

- Productivity.
- Magic.
- Seamless.
- Copilot.
- Workflow transformation.
- AI-native operating layer.

## Claims To Avoid Until Proven Publicly

- Fully autonomous.
- Enterprise-grade security.
- Works with every tool.
- Zero setup.
- Perfect accuracy.
- Replaces your team.

## Claims To Use

- Reviewable.
- Scoped.
- Tool-using.
- Specialist.
- Sandboxed.
- Shareable.
- Built for real work.

## Visual Strategy

The page should show product surfaces early. Notion can rely on brand familiarity; Hivy needs proof. The hero should include a real session or a composed product screenshot, ideally showing:

- Agent selected.
- Tool activity.
- A generated artifact or preview.
- Review/comment controls.

Avoid a generic abstract AI hero. The product's advantage is concrete work, so the visual system should look operational and inspectable.

## CTA Strategy

Primary CTA:

Start free.

Secondary CTA:

View on GitHub.

Sales CTA:

Talk to us, only if enterprise features are ready enough to support procurement conversations.

The repeated CTA should ask visitors to start with one task, not adopt an entire platform.

## Best Borrowed Lesson From Notion

Pair autonomy with control in the same breath. The more the copy says agents can act, the faster it should show the user how the team can inspect, scope, and correct that action.
