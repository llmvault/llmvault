# What Hivy must build

## The product bet

Don't compete on “best chat.” Compete on dependable company work.

ChatGPT, Claude, and Grok can all search, reason, create files, use tools, and run agents. Model quality will keep moving. Hivy needs an advantage that survives the next model release: company-owned agents with one control system across cloud, browser, desktop, mobile, and private infrastructure.

## What every serious buyer now expects

### Work continues after chat

Users expect tasks that run in the background, follow a schedule, survive app closure, ask questions, and resume later. Grok Bot raises the bar further: an agent may work inside a persistent signed-in cloud computer, follow a stalled handoff, or coordinate with other agents. Hivy needs a work item, shared inbox, clear states, checkpoints, and human takeover across all of those cases.

### Company knowledge respects source access

Connecting Drive or SharePoint isn't enough. Search must preserve the employee's current rights, cite the exact source, show sync age, and remove revoked material quickly.

### Agents can act, but the company stays in charge

People want email, calendars, tickets, CRM, finance, code, browsers, and desktop apps. Admins need to allow one action while blocking another, set amount and destination limits, require one or two approvals, and stop access fast.

### The same task moves across devices

Web is best for building and oversight. Desktop can reach local files and apps. Mobile is best for voice, camera evidence, alerts, and approvals. Users should see one task and one history, not three products.

### Outputs are real work products

Documents, slides, spreadsheets, PDFs, reports, images, and small apps need native files, previews, versions, comments, citations, and exact approval. A download link alone isn't enough.

### Business admin is part of the product

MFA, SSO, domains, sessions, budgets, audit, retention, deletion, and honest legal pages belong in the Business offer. SCIM, custom roles, compliance exports, regional rules, customer keys, private execution, and SLAs belong in Enterprise.

## Where Hivy should differ

### Team-owned agents

An agent should have a team, accountable owner, job, version, knowledge rights, action rights, budget, tests, release state, and outcome history. That is more useful than another personal assistant profile.

### One action system everywhere

A Salesforce update, MCP call, browser click, desktop keystroke, shell command, and generated-app write should all create the same action intent. One trusted service then checks capability, policy, approval, execution, and result.

### Cost per accepted result

Token counts don't tell a finance lead whether the work paid off. Hivy should measure what each accepted invoice, account brief, incident response, report, or code change cost.

### Unlimited reviewers

If pricing allows it, unlimited collaborators can become a real advantage. Many people need to request, review, or approve agent work without using models all day.

### Clear local and private execution

Hivy already has a local runtime and infrastructure base. Make execution location visible, policy-controlled, and available for customer environments. Don't blur local work into cloud work.

### Teach by showing, then review before trust

Grok Bot can watch someone perform a job and save the steps as a routine. Hivy should support the same short path, but it must convert the recording into a versioned routine with clear inputs, outputs, permissions, tests, and an owner.

Corrections can propose a new version. They can't rewrite a live routine in the background. Proactive work should grow through explicit trust levels based on accepted results and policy, not a vague promise that the agent “learns over time.”

## Business plan: minimum bar

| Work | Company control |
|---|---|
| Durable inbox, schedules, and proactive follow-up rules | MFA, SSO, verified domains, sessions, and devices |
| One task across web, desktop, and mobile | Connector and MCP action rules |
| Company search with source access and citations | Approvals tied to the exact payload |
| Native documents, slides, spreadsheets, and PDFs | Budgets, cost assignment, and reliable audit |
| Reviewed routines taught by demonstration | Published legal, security, support, and status information |
| No training on company data by default | Persistent cloud workspace with isolated credentials |

## Enterprise: minimum bar

| Identity and data | Infrastructure and service |
|---|---|
| SCIM and directory groups | IP, device, MDM, and private-network controls |
| Custom roles and separation of duties | Dedicated or customer-cloud execution |
| Retention, deletion proof, legal hold, and exports | Contractual SLA, onboarding, and named support |
| Compliance and analytics APIs plus SIEM | Customer-managed keys with exact coverage |
| Storage and model-region rules | |

## Build order

Rules and evidence come before broad autonomy. Build durable work, action manifests, policy, approvals, and audit first. Then expand mobile, desktop, company knowledge, agent releases, routine capture, and computer control. Enterprise data controls follow once the core records and storage registry exist.

Delay video, huge connector counts, and a general workflow canvas until common business work is reliable.

## Decision test

For every planned feature, ask four questions:

1. Does it help an agent finish company work?
2. Can the company limit and inspect it?
3. Does it work with Hivy's shared work-item model?
4. Can we prove what happened after failure?

If the answer to one is no, the feature isn't ready for production.
