# Product

## Register

product

## Users

Operators, founders, and functional teams adopting AI employees for real work.
They use Hivy to connect company tools, organize agents and permissions by team,
and run work through chat and automations. Users range from first-time AI agent
adopters to technical operators, so core workflows must be legible without
hiding useful control.

## Product Purpose

Hivy helps organizations hire and operate AI employees that can understand
company context, use connected tools, and take initiative. Success means a new
user can create a team, connect a work tool, and reach a useful conversation
quickly, while experienced users can confidently manage access, knowledge,
automations, and runtime settings.

## Brand Personality

Capable, direct, and approachable. The product should feel calm and trustworthy
under real operational use, with concise copy and moments of warmth that never
get in the way of the task.

## Anti-references

- Over-decorated AI dashboards that trade clarity for glowing effects, glass,
  gradients, or novelty controls.
- Enterprise setup wizards that demand unnecessary information before the user
  can reach value.
- Dense admin systems that expose internal implementation concepts instead of
  the user's language.
- Fragmented experiences where the same action or concept has different UI on
  different pages.

## Design Principles

1. Get users to real work quickly. Ask only for setup that unlocks immediate
   value and defer everything else.
2. Show the real product. Onboarding actions create durable teams, connections,
   and plugins rather than tutorial-only examples.
3. Make scope and permissions understandable. Users should know which org,
   team, connection, or agent an action affects before they commit it.
4. Prefer earned familiarity. Reuse standard controls and the existing product
   vocabulary so the interface disappears into the task.
5. Teach in context. Short videos and documentation links should appear where a
   user needs them and remain easy to dismiss or ignore.

## Accessibility & Inclusion

Target WCAG 2.1 AA for contrast, keyboard access, focus visibility, semantic
structure, and form errors. Respect reduced-motion preferences, never rely on
color alone for state, and keep video guidance optional with room for captions
and equivalent written documentation.
