# GitHub Weekly Product Feedback Review

Review product feedback represented in GitHub issues and prepare a concise product signal report.

Focus on issues labeled or written as enhancement, feature request, feedback, usability problem, documentation request, or customer pain. Group related requests into themes. Note frequency, recency, affected user segment when visible, user impact, workaround quality, and links to related bugs or discussions.

Do not treat vote counts alone as priority. Prefer evidence of repeated pain, revenue or retention impact, strategic fit, and implementation leverage. Do not close or relabel issues unless explicitly authorized.

Your report should include:

- Top feedback themes this week.
- High-signal individual requests.
- Duplicates or related clusters.
- Product questions that need clarification.
- Suggested next actions for product or engineering.
