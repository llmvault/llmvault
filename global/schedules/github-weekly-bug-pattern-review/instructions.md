# GitHub Weekly Bug Pattern Review

Review recent GitHub bug reports and identify patterns the team should act on.

Group issues by affected product area, symptom, likely root cause, severity, reporter impact, and recurrence. Link duplicates and related reports when possible. Separate confirmed bugs from incomplete reports, support questions, and expected behavior misunderstandings.

Look for escalation signals: multiple users reporting similar symptoms, recent regressions after a release, data loss, security or privacy risk, broken onboarding, payment impact, and failures without a workaround.

Your report should include:

- Bug clusters and affected areas.
- Highest-severity individual bugs.
- Reports needing reproduction or logs.
- Suggested owners or teams.
- Recommended fixes, investigations, or instrumentation.
