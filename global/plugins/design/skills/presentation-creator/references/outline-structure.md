# Outline Structure

Define the narrative arc and slide sequence before writing slide copy or drawing boards.

## Standard Flow

```text
Opening -> Context / tension -> Core proof or proposal -> Ask / next step
```

- **Opening:** title, audience relevance, and at most three outcomes.
- **Context:** current state, tension, urgency, or decision pressure.
- **Core sections:** two to four sections that each move the audience closer to the action.
- **Closing:** recap, decision, ask, next step, resources, or Q&A.

## Slide Types

| Type | Purpose | Example |
|------|---------|---------|
| statement | Land a key point | "Manual review is now the bottleneck" |
| big-statement | Maximum impact | "The old workflow cannot scale" |
| question | Create tension | "What changes if support volume doubles?" |
| section-divider | Signal a topic shift | "Where the risk lives" |
| goals | Set expectations | "What we need to decide today" |
| data | Prove with numbers | "Expansion revenue grew 38%" |
| framework | Make a model memorable | "Cost, risk, adoption" |
| product-proof | Show the thing | Screenshot, flow, or before/after |
| case-study | Borrow credibility | Customer, challenge, result |
| quote | Add human evidence | Customer or research quote |
| objection | Remove friction | Risk and response |
| recap | Summarize the argument | One line per section |
| next-steps | Drive action | Owner, date, decision, CTA |

## Business Arc Patterns

### Executive Decision

```text
Recommendation -> Why now -> Evidence -> Options -> Risk -> Decision needed
```

Lead with the answer. Executives need the decision frame before the supporting details.

### Sales or Proposal

```text
Their world today -> Cost of status quo -> Better future -> Proof -> Plan -> Investment -> Next step
```

Use the buyer's language from discovery. Every slide should help them believe change is worth it.

### Product or Feature Launch

```text
Audience pain -> New capability -> User value -> Proof -> Rollout -> CTA
```

Show outcomes before feature detail.

### Stakeholder Review

```text
Goal -> Constraints -> Options considered -> Recommendation -> Evidence -> Ask
```

Separate what is decided from what still needs feedback.

## Outline Output Format

```markdown
# [Deck Title]
[Audience, setting, desired action]

## 1. Opening

### Slide 1: [Title]
- Type: statement
- Job: establish relevance
- Headline: [Complete claim or useful title]
- Supporting: [Subtitle, date, presenter, or context]

### Slide 2: [Decision frame]
- Type: goals
- Job: tell the audience what will be decided
- Points:
  - [Point 1]
  - [Point 2]
  - [Point 3]

## 2. [Section Name]

### Slide 3: [Slide purpose]
- Type: [statement/data/framework/product-proof/etc.]
- Job: [context/proof/confidence/action]
- Headline: [Claim]
- Supporting: [1-2 lines, bullets, metric, or visual direction]

## N. Close

### Slide N: [Ask]
- Type: next-steps
- Job: make the next action obvious
- Headline: [Clear ask]
- Supporting: [owner, date, CTA, or decision]
```

## Workflow

1. Identify audience, setting, desired action, and three messages.
2. Pick the deck mode: live, async, sales, proposal, investor, executive, or review.
3. Map the arc before drafting slide copy.
4. Label each slide with its job.
5. Cut any slide that does not create context, proof, confidence, or action.
6. Only then start building Canvas boards.
